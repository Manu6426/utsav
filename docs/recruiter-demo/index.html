The Problem

Planning a celebration shouldn't mean 40 open tabs

Booking a decorator, a photographer, a caterer, a DJ and a makeup artist for one event usually means bouncing between Instagram pages, word-of-mouth referrals and spreadsheets — with no easy way to compare vendors side by side, keep the whole plan inside one budget, or book without a phone call. Existing marketplaces are generic; none speak the language of multicultural celebrations where one event can span a mehendi, a sangeet and a reception.

The Solution

One marketplace, from discovery to booking

Utsav is a single-page web app that brings the whole flow together: a rule-based concierge that matches vendors to your occasion, city and budget; a budget freeze that keeps every browse and bundle inside your limit; a team builder that bundles vendors with a combined price; and a booking flow that issues a confirmation reference. Everything runs client-side today — fast, offline-friendly, and deployable as a single static file.

Working today

Front-end demo, fully interactive

Hash-routed views (Home, Browse, Vendor profile, Compare, Team builder, Onboarding, My bookings, Occasions), 21 seeded vendors across 8 categories, filters by city / category / price / rating, and all state persisted in localStorage. The only network call is an optional geo lookup.

Production roadmap

Java backend planned next

The production design is a Spring Boot REST API backed by PostgreSQL — real vendor accounts, bookings persisted server-side, authentication, and payments. See the architecture and roadmap sections below.

Key Flows

What the app actually does

🤖 AI concierge (rule-based matching)

Type a request in plain language — "wedding photographer in Boston under $3000" — and a keyword parser extracts the occasion, city, budget, currency and guest count, then scores vendors by rating, verification status, city and budget fit.

It's a deterministic matching engine, not an LLM: transparent, instant, and it runs entirely in the browser with zero API cost.

❄️ Budget Freeze

Set a total budget once, and it stays frozen across the session: browsing, filters and the team builder all respect it, showing only vendors and combinations that fit inside the cap.

The frozen budget persists in localStorage, so a planner can close the tab, come back tomorrow, and pick up exactly where they left off.

👥 Team builder

Bundle up to three vendors into one event team — photographer plus caterer plus DJ, for example — with a combined price computed live as you add and remove vendors.

Combined with Budget Freeze, the team builder acts as a real planning tool: it tells you immediately whether your dream team fits the budget, before you book anything.

📅 Booking with reference numbers

Pick a date, a time slot and enter a name and phone number to book — the app issues a UTS-XXXXXX reference and shows "No payment due now," so there's no ambiguity about what happens next.

Bookings live under "My bookings" with the vendor, date, slot and reference, and a vendor onboarding form lets new vendors submit their own listing for review.

Why this order: the SPA was built first to validate the product — the concierge matching, budget freeze and team-builder flows — with real user interactions before committing to a backend schema. The API design follows directly from the data model the front end already uses (vendors, bookings, teams), so the Spring Boot build is a migration of proven logic, not a rewrite of guesses.

Scope honesty: Utsav today is a front-end SPA demo — there is no Java backend, no database, no authentication and no payments yet. Everything described above as "planned" is genuinely planned: the production architecture is designed and the front-end data model was built to migrate cleanly into it.
